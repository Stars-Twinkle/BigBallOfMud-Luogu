# BigBallOfMud Luogu

洛谷新版前端（columba / lfe）的**液态玻璃**美化 + **深浅双模式**。

**只需要装一个油猴脚本** —— 样式已经打包进脚本里，由它在 `document-start` 注入
（比 Stylus 还早，不会闪白）。**不用装 Stylus，也不用装任何 UserCSS**。

脚本自己负责两件事：注入全部外观，以及页面内可点的三态配色开关、深色下的**对比度校正**。

## 都美化了哪些地方

- **液态玻璃质感**：不是单纯的毛玻璃 —— 有镜面光斑、亮上缘 / 暗下缘的"厚度"、内发光，
  以及**小半径模糊 + 洗淡（低饱和）**带来的通透感；鼠标悬停时光斑会缓慢漂移
- **边缘折射**：玻璃边缘的背景会被真实地弯折（不是模糊，是位移）。做法是把圆角矩形的
  距离场编码成位移图，再用 `feDisplacementMap` 在 `backdrop-filter` 里做采样偏移 ——
  详见下面的「边缘折射」一节
- **顶栏**：左右两个独立的玻璃胶囊，中间留空；高度与留白全站统一
- **左右侧栏**：悬浮胶囊（离开屏幕边缘 + 大圆角），滚动条隐藏，展开/收起状态各自正确
- **背景图**：透出到整页（洛谷默认只画顶部 400px 且有一层不透明底板挡住了图）
- **深色模式**：覆盖洛谷运行时注入的调色板令牌、写死的浅色文字、白底控件、
  各类弹窗与编辑器（SweetAlert2 / CodeMirror 6 / Casket / 题目排序面板 / 评测测试点方块…）
- **链接悬停**：渐变色文字 + 下划线从中间划入（犇犇、讨论区、文章正文都覆盖）
- **标签 / 徽章悬停**：一道高光扫过 + 轻微抬起
- **卡片、按钮、表单、浮层**：同一套玻璃语言，并带柔和阴影与悬停反馈
- **洛谷网校**（`class.luogu.com.cn`）：首页、播放页（课堂）、学习中心的侧栏 / 顶栏 / 播放区 /
  控制条 / 聊天面板与输入框 / 课程卡 / 分类卡 / 页脚 / 标签栏，都按各自前端产物逐条适配，
  深浅色与玻璃一致；「学习体系」那张大图抠掉底板后由玻璃承载

## 音乐播放器

脚本在 `www.luogu.com.cn` 上挂一颗 44px 的小圆球，点开是完整的播放器面板。
**只在主站出现**（网校不注入），窗口宽度小于 900px 时也不挂。
圆球可以拖到屏幕任意一条边吸附，面板朝有空间的那一侧展开，贴边时会自动往回收，不会出屏。

### 它有什么

- **三种导入**：本地音频（点封面选，或直接把文件拖进页面）、音频直链、网易云歌曲 ID / 歌单链接
- **歌单**按文件夹显示，每个歌单可以单独设播放模式：顺序 / 随机 / 列表循环 / 单曲循环
- **每首歌都能改**：歌名、作者、封面（上传或贴图链）、字幕；也能把音频换成另一个文件或另一条链接
- **歌词自动获取**：导入时顺带拉一次，切到某首时发现还没有就再补一次。
  支持 LRC 的 `[offset:±ms]` 整体偏移、一行多个时间戳、整段没有换行
- **字幕行常驻**：没有歌词时只藏内容、保留位置，面板高度不会随歌词有无而跳
- **跨页续播**：换页面或刷新后接上上次那首和进度，真正开始播放仍由播放键触发
  （浏览器的自动播放策略要求用户手势，这是绕不过去的）
- **日志导出**：面板右上角的 ⤓ 按钮，出问题时导一份出来就能定位

### 为什么网易云的歌要先下载

洛谷在页面 HTML 里用 `<meta http-equiv="Content-Security-Policy">` 写了 `default-src`，
白名单里只有洛谷自家域名、阿里云 OSS、网易的几个静态资源域（`nosdn` / `cstaticdun`）、
`cloudflare` 验证码，外加 `blob:`。**没有单独的 `media-src`**，所以媒体请求回退到 `default-src`。

于是把 `https://music.163.com/song/media/outer/url?id=…` 直接交给 `<audio>`，
浏览器在**请求发出之前**就拦掉，元素层只报 `error 4`，原文是
`MEDIA_ELEMENT_ERROR: Media load rejected by URL safety check`。
（把同一个地址粘到地址栏却能播 —— 顶层导航不受页面 CSP 约束。）

所以：**有本地副本就直接用，没有才去取**。导入后会在后台用 `GM_xmlhttpRequest` 预取成 Blob、
存进 IndexedDB（扩展发起的请求不受页面 CSP 限制，`blob:` 又在白名单里），
列表里标 `✓ 已缓存`。

播放时的顺序（2026-10-27 调整）：**缓存命中就直接播本地副本**，不再先拿直链去撞 CSP ——
"先失败再兜底"要多一个异步往返，等兜底回来时已经脱离用户手势窗口，`play()` 会被拒，
表现就是切完歌停在 0:00。没有缓存的歌才试直链，被拦了再兜底下载。
所以哪天洛谷放开这条策略，没缓存的歌走直链也会直接生效。

### 数据存在哪

| 内容 | 位置 |
|---|---|
| 歌名 / 作者 / 封面 / 字幕 / 歌单结构 | `localStorage` 的 `bomPlayer.lib.v2` |
| 音频数据（本地文件 + 下载来的直链音频）| `IndexedDB`，同一个库里用歌曲 id 作 key |
| 续播状态 | `localStorage` 的 `bomPlayer.resume.v1` |

删歌会把 `IndexedDB` 里那份音频一起删掉。
`IndexedDB` 是按来源隔离的，所以主站和网校不共享本地音频（播放器本来也只在主站出现）。

### 已知限制

- 网易云外链只有免费 / 有版权的歌能拿到内容，VIP 歌会在列表里标 `⚠ 版权受限`
- 变速版本（Slowed / 加速）用的仍然是原曲的歌词时间轴，会整体错位
- 波形图目前是 CSS 动画占位：跨域音频接 `AnalyserNode` 会被 AudioContext 静音，
  真实频谱要等音频层再调整

## 自定义机制（想调一调？）

### 三个入口

| 入口 | 在哪 | 管什么 |
|---|---|---|
| **顶栏按钮** | 顶栏那个圆形图标 | 跟随系统 / 深色 / 浅色三态循环，选择被记住（这是**唯一**的配色入口）|
| **样式里的 CSS 变量** | 样式 ② 段（玻璃参数）、③ 段（光泽与文字色）、⑭ 段（背景图） | 外观的全部数值：透明度、模糊、圆角、尺寸、颜色、背景图 |
| **脚本里的 CONFIG** | `bigballofmud-luogu-switch.user.js` 顶部的 `var CONFIG = { … }` | 行为开关：配色按钮、对比度守卫、守卫门槛、防抖时长、调试日志 |
| **脚本里的折射常量** | 脚本内 `var REFRACT_* = …` 一组 | 边缘折射：强度、带宽、总预算、面数上限（详见下面的「边缘折射」一节）|

> 改完 CSS 变量要 **Ctrl+S 保存 + 页面 Ctrl+F5**；改脚本要 **Ctrl+S**（篡改猴即时生效，一般不必刷新）。
> 样式里所有可调项都集中在上面那几段，**不必翻全文**：搜索变量名即可（变量名都以 `--lg-` 或 `--sl-` 开头）。

### 哪些东西跟着「洛谷主题商店」自动变

基本约定：**样式自己接管背景与玻璃的呈现**，主题商店只负责"给你选的东西"。
所以下面这张表要配合上一节的「设置变少」一起看 —— 被隐藏的那几项，对应的跟随关系也就断了。

| 项目 | 跟随主题？ | 现在的实际行为 |
|---|---|---|
| **背景图**（编辑器里的「背景图」那一项）| **跟随** | 你填的地址会被脚本读到，搬到 `<html>` 当画布背景（首页与网校复用同一张）|
| ↳ 背景图的**尺寸 / 重复 / 位置** | **不跟随** | 对应设置项已隐藏，画布统一 `cover` + `fixed` + `center` |
| **导航背景** | **跟随** | 这一项保留，顶栏胶囊与左右侧栏都消费 `--theme-navi-back` |
| **Logo 颜色** | **跟随** | 这一项保留 |
| **导航文字 / 图标颜色** | **固定为默认白** | 对应的「文字颜色」项**会先固定回白色再隐藏**（它同时影响图标，而深色下选什么都渲染成白）|
| **页面底色 / 中景颜色** | **不再跟随** | 对应的「背景底色」「中景颜色」已隐藏，底色由画布背景 + 压暗层决定 |
| **卡片底色** | **浅色跟随 / 深色不跟随** | 浅色分支就地消费 `--theme-card-background`（玻璃底 = 主题卡片色 × `--lg-alpha`）；深色分支用我们给的 `--lg-*-dark` 那一套（主题基本只配浅色）。**删掉主题色会回落到白色**，所以玻璃会变纯白底 —— 那不是跟随失败，是主题真的没色了 |
| **洛谷的语义色**（标签、难度、AC/WA、`lcolor-*`）| **原样保留** | 一律不动，包括我们新加玻璃的那批标签（只叠玻璃，不改它们的底色）|
| **正文与次要文字颜色** | **不跟随** | 用 `--lg-text` / `--lg-text-weak`，保证深浅两种模式下都可读 |
| **深色模式的底色** | **不跟随** | ③-c 段那七个 `--lg-*-dark`（含大容器的 `--lg-panel-large-dark`）是我们给的一套暗值（主题基本只配浅色）|
| **毛玻璃等级** | **不跟随** | 洛谷的 `theme-frosted` 伪元素已关闭，全站统一用 `--lg-blur` / `--lg-card-blur` / `--lg-sat` |

**一句话**：**背景图、导航背景、Logo 颜色**这三样由你在主题商店里决定，其余外观都由样式的变量控制。

> ⚠️ 别把样式里浅色分支的 `--theme-*` 改成固定颜色 —— 那会锁死主题色，主题商店换色时玻璃就不跟着变了（早期踩过）。

### 玻璃通透度（数值越小越透）

| 变量 | 默认 | 管什么 |
|---|---|---|
| `--lg-alpha` | `14%` | 主卡片 |
| `--lg-alpha-soft` | `10%` | 列表 / 表格 / 分页 / 搜索框 |
| `--lg-alpha-pop` | `14%` | 模态 / 下拉 / 气泡 / 通知（与卡片同值，避免色差）|
| `--lg-alpha-field` | `30%` | 输入框 / 文本域 / 下拉选择 |
| `--lg-nav-alpha` | `26%` | 顶栏两个胶囊 + 左右侧栏 |
| `--lg-alpha-large` | `22%` | 大面积容器（旧首页 `.lg-article` / 页脚 / 新前端主卡）单独一档 |

> 大容器为什么单独一档：它们面积 18~60 万 px²，模糊半径被压到 `--lg-blur-large`（2px），
> 只靠 14% 的白压不住花壁纸，所以底色略实一点。

### 液态玻璃质感

| 变量 | 默认 | 作用 |
|---|---|---|
| `--lg-blur` | `6px` | 浮层 / 顶栏 / 侧栏的模糊半径 |
| `--lg-card-blur` | `3px` | 普通卡片模糊 |
| `--lg-blur-large` | `2px` | 大面积容器（面积越大半径越小，成本 ∝ 面积 × 半径）|
| `--lg-sat` | `105%` | 背景饱和度。**不是越高越好** —— 苹果的玻璃把背景"洗淡"，所以这里几乎不加饱和 |
| `--lg-spec` | `32%` | 镜面光斑强度（设 `0` 退回普通毛玻璃）|
| `--lg-rim` | `88%` | 上缘高光强度（玻璃厚度感）|
| `--lg-border` | `.88 / .34` | 外侧 1px 亮描边（**Apple 的高级感主要来自它**，不是模糊）|
| `--lg-rim-color` | `.80 / .32` | 内侧上缘亮线颜色 |
| `--lg-shade` | `.16 / .30` | 背光侧暗缘（有它才有体积感）|
| `--lg-glow` | `.07 / .028` | 内发光 |

> **为什么模糊这么小**：参考 iOS 26/27 的 Liquid Glass 截图，Dock、播放器卡里的背景细节
> 都清晰可辨（约 2~3px），"苹果感"来自**亮描边 + 边缘折射 + 洗淡**，不是来自大模糊。
> 早期版本用过 18~24px 的模糊 + 215% 饱和，观感是"脏"和"廉价"。

### 边缘折射

玻璃边缘的背景会被**真实弯折**，这是纯 CSS 做不到的部分，由脚本实现：

```
① 用圆角矩形 SDF 算出每个像素到边缘的距离
② 把「弯折方向 + 强度」编码成一张位移图（R = x 位移、G = y 位移，中性值 128）
③ 建 <filter>：<feImage> 载入位移图 → <feDisplacementMap> 按 R/G 通道做采样偏移
④ 给元素写 backdrop-filter: blur() … url(#id)（裸 url() 会被 Blink 静默忽略，前面必须有滤镜函数）
```

| 常量 | 默认 | 作用 |
|---|---|---|
| `REFRACT_AMOUNT_RATIO` | `0.09` | 位移 = 短边 × 这个值（所有玻璃统一，不按面积分档）|
| `REFRACT_AMOUNT_MAX` | `20` | 位移绝对上限（防撕裂：位移必须小于采样点到元素边的距离）|
| `REFRACT_BEZEL_RATIO` | `0.18` | 弯折覆盖的带宽 = 短边 × 这个值 |
| `REFRACT_BEZEL_MAX` | `70` | 带宽绝对上限 |
| `REFRACT_BUDGET` | `3e6` | **总像素预算 —— 性能与覆盖面的兑换旋钮** |
| `REFRACT_MAX` | `40` | 面数兜底上限 |

**衰减曲线**是 `t^2.2`（`t` 在元素边界处为 1、往内趋 0）—— 越靠边缘越狠，中心平坦，
这正是 iOS 截图里的表现（资源库文件夹边缘的图标被极度拉伸、中心几乎不变形）。

**三道门禁**（任一不过就安静放弃、只保留纯模糊）：

1. **引擎**：`backdrop-filter` 里放 `url()` 是 Blink 扩展，Safari / Firefox 会解析但不画，
   而 `@supports` 会误报 ⇒ 按 UA 判引擎，再建一条最小滤镜验证计算值里真的保留了 `url()`
2. **CSP**：洛谷的 `<meta>` CSP 若不放行 `img-src data:`，位移图会被静默拒掉 ⇒ 先探一次
3. **backdrop root**：祖先带 `filter` / `opacity < 1` / `mask` 会切断折射，这些元素跳过
   （**注意：`position: fixed` 不会切断**，早期按 fixed 判断导致大量元素被误跳过）

> ⚠️ **覆盖面和帧率是直接兑换关系**。每条带折射的玻璃都是一条**每帧重新光栅化**的滤镜链。
> 实测同一页滚动 30 帧（headless，无 GPU）：预算 130 万 → 1496ms、300 万 → 约 1800ms、
> 不设限 → 2890ms。觉得卡就把 `REFRACT_BUDGET` 调小，想看更多玻璃有折射就调大。

> 想看当前状态：控制台执行
> `document.documentElement.getAttribute('data-sl-refract')`，
> 会显示「成功 N 个；跳过：…」以及每个候选被哪条规则筛掉。

### 背景图

**默认行为：跟着洛谷主题商店走** —— 样式里 `--sl-bg-image` 是**留空**的，
由脚本去读洛谷主题设置的图（`--theme-body-image`，洛谷把它放在 `.theme-page` 上，
真正画图的是 `.theme-page::before`；`<html>` 上取不到这个变量，所以必须由脚本搬一次），
把结果写到 `<html>` 的 `--sl-bg-active`。
**分三种情况**：① 读取到地址 → 用它；② 主题里那一项**被清空** → 回滚成洛谷自己的默认中景图
（`luogu4-bg-l/d`）并清掉缓存；③ 页面还没渲染出 `.theme-page`（或旧首页本来就没有）→ 只用手上的缓存，缓存也空就什么都不写，**故意不写默认图**，免得先闪一下再被真图替换。

> ⇒ **要用主题商店的背景图，脚本必须装**。缺脚本时画布上没有图，只剩底色（与压暗层）。

**脚本侧的抓取规则**（不用改，只是说明）：主站**每次页面更新**先把缓存作废、再重新读一次中景图并写回缓存；
网校与首页自己页面上没有这个变量，直接**复用缓存**；缓存用篡改猴的跨域存储（`GM_setValue` / `GM_getValue`）——
`localStorage` 是按域名隔离的，网校读不到主站存的。

### 主题编辑器里为什么「设置变少了」

脚本会把洛谷主题编辑器（`/theme/…`）里**与美化冲突**的那几项直接隐藏，所以你会看到设置项比原版少。这是有意的：本样式自己接管了背景与玻璃的呈现，那些参数留着只会互相打架（有的还会让渲染不对）。

| 被隐藏的项 | 为什么 |
|---|---|
| **卡片毛玻璃** | 美化是照默认的「**标准**」档写的，选「关闭 / 轻量」会导致渲染不对。脚本会**先把档位拉回「标准」再隐藏** |
| **渐变角度 / 中景亮度 / 中景淡出** | 背景的呈现由本样式接管（画布 + 压暗层），这几个参数进去会互相打架 |
| **图片重复 / 图片尺寸 / 图片位置 X / Y** | 同上。画布统一用 `cover` + `fixed`，由样式决定 |
| **背景底色 / 中景颜色** | 与画布背景、玻璃底色冲突 |
| **亮色主体**（区块标题） | 它下面那几项都已隐藏，标题留着没有意义 |
| **文字颜色** | 它**同时影响图标**，而深色模式下不管选什么颜色最后都会渲染成白，所以脚本会**先把它固定回默认白色再隐藏** |

**保留下来的项**：**导航背景**、**Logo 颜色**、以及 **「背景图」**。

> 最后那个是把原来的「中景图片」改了名字（脚本原地改文案）—— 它就是**唯一还需要你设的一项**。
> 填进去的地址决定全站用哪张背景图，首页与网校会在你打开一次主站内页后跟着用同一张。

> 想恢复被隐藏的项：把脚本里 `THEME_HIDE_PREFIX` 数组中对应的那一行删掉即可（在 `tweakThemeEditor()` 上方）。
> 两项「前置动作」（卡片毛玻璃 → 标准、文字颜色 → 白）在 `tweakThemeEditor()` 里有单独的注释说明。

## 常见问题

**Q：装上之后右栏收不回去了？**
已经修好了。如果你想改侧栏悬浮参数：`--lg-side-gap`（离边缘距离）、`--lg-side-radius`（圆角）。

**Q：深色下某处还是白的 / 某段文字看不清？**
两件事可以试：
1. 确认脚本是最新版（篡改猴管理面板 → 「检查更新」；或比对 `@version` 日期）
2. 装上脚本（必需）—— 它的「对比度守卫」会读取**最终计算出来**的颜色，自动把不达标的文字修到可读

**Q：浅色模式和洛谷原版一样吗？**
一样。样式的浅色分支一律"就地消费"洛谷的主题变量，且深色重映射用的浅色值都等于洛谷原值
（本项目有一套校验脚本专门断言这一点）。

**Q：首页那块广告轮播能藏掉吗？**
能。样式的做法是「**默认显示**」——广告保持洛谷原样，
所以在样式里搜 `把下面两行取消注释即可`（或直接搜 `#lg-slider`），
把那段被注释掉的规则放开即可，**同时**要把紧跟着的 `.lg-punch`（打卡/日历列）也放开到整行，
否则左边会空出 2/3。两段都写在一起了，一起放开就行。

**Q：会和洛谷主题商店冲突吗？**
不会。样式不重写主题变量，只是消费它们；换主题色、换背景图，玻璃都会跟着变。

**Q：页面变卡？**
按这个顺序试：
1. **调小折射预算** —— 这是最有效的一档，改脚本里的 `var REFRACT_BUDGET = 3e6;`
   （1.5e6 大约砍掉一半折射面）。每条带折射的玻璃都是每帧重新光栅化的滤镜链，覆盖面越大越吃性能。
2. 把 `--lg-card-blur` 调到 `0`（面积 × 半径才是成本，卡片的面积通常最大）。
3. 把 `--lg-sat` 降到 `100%`（几乎不额外合成）。

**Q：为什么折射只挂在部分玻璃上、有的地方没有？**
因为它是**按面积预算挑的**，不是每个玻璃都给。控制台看
`document.documentElement.getAttribute('data-sl-refract')` 会告诉你成功了几个、其余被哪条规则筛掉；
常见原因是「祖先有 filter/opacity/mask」（真的会切断折射）或「面积超过单面上限」。
想多给就把 `REFRACT_BUDGET` 调大。

**Q：折射边缘有一道浅色接缝 / 圆角处露出亮边？**
已修：位移在元素边界处改成 6px 线性羽化（原来边界处是满值、一过界就归零，会在 45° 方向留下接缝）。
如果还能看到，把 `--lg-border` 从 `.88` 降到 `.7` 试试（那是描边，不是折射）。

**Q：为什么模糊设得这么小（2~3px）？**
参照 iOS 26/27 的 Liquid Glass 截图：Dock 和播放器卡里的背景细节都清晰可辨，
"苹果感"来自亮描边 + 边缘折射 + 把背景**洗淡**（低饱和），不是来自大半径模糊。
早期版本试过 18~24px 模糊 + 215% 饱和，结果是"脏"和"廉价"。

**Q：手机上能用吗？**
未测试。样式是按桌面布局写的（顶栏胶囊、左右侧栏），移动端布局不同，可能需要另外适配。

## 兼容性

- **浏览器**：需要支持 `light-dark()`，即 Chrome / Edge 111+、Safari 16.4+、Firefox 120+。
  更老的浏览器会退化：文件里有 `@supports not (color: light-dark(#fff, #000))` 兜底块，
  保留固定浅色玻璃（深色模式不生效）。
- **边缘折射只有 Chromium 内核有**：`backdrop-filter` 里放 `url(#filter)` 是 Blink 的扩展，
  Firefox / Safari 会把它解析掉但不绘制。脚本会先做能力探测，不支持就**安静跳过折射**
  （玻璃、模糊、描边、深浅色全部照常，只是边缘不会被弯折）。
- **站点范围**：主站 `www.luogu.com.cn` 与**网校** `class.luogu.com.cn`（首页 / 播放页 / 学习中心等
  已按各自产物适配，深浅色与玻璃都覆盖）。
  `ti.luogu.com.cn`（有题）是另一套前端，暂不覆盖。
- **随洛谷更新可能失效**：洛谷前端发版会改 DOM 结构与类名。本样式**刻意不使用** `data-v-*` 哈希
  （每构建都会变），但仍然依赖稳定的语义类名，洛谷大改版后个别地方可能需要跟进。
