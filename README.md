# BigBallOfMud Luogu

洛谷新版前端（columba / lfe）的**液态玻璃**美化 + **深浅双模式**。

纯 CSS 实现，不需要油猴脚本也能用；想要"页面内可点的配色按钮"和"深色对比度自动校正"，
再额外装那个可选脚本即可。

---

## 两个文件是什么

| 文件 | 装到哪 | 必需？ | 作用 |
|---|---|---|---|
| [`bigballofmud-luogu.user.css`](bigballofmud-luogu.user.css) | **Stylus**（或其它 UserCSS 管理器）| **必需** | 全部外观：液态玻璃、深浅配色、顶栏胶囊、侧栏、链接悬停、标签动画…… |
| [`bigballofmud-luogu-switch.user.js`](bigballofmud-luogu-switch.user.js) | **Tampermonkey**（油猴）| 可选 | ① 顶栏放一个可点的三态配色开关（选择被记住）② 深色下自动修正对比度不足的文字 |

> 两个文件是**配合**关系：脚本只负责"行为"，一行 CSS 都不注入；
> 样式只负责"外观"，不写任何 JS。所以可以只装样式、也可以两个都装。

## 安装

### 1. 样式（必需）

**方式 A：从 URL 安装（推荐，方便以后更新）**

1. 装 [Stylus](https://add0n.com/stylus.html) 扩展
2. 打开 Stylus 管理面板 → 「**编写新样式**」→ 把下面这个 raw 链接粘进样式正文里
   （Stylus 会自动识别 `==UserStyle==` 头；若你的版本没有"从 URL 安装"，用方式 B）：
   `https://raw.githubusercontent.com/Stars-Twinkle/BigBallOfMud-Luogu/main/bigballofmud-luogu.user.css`

**方式 B：手动粘贴**

1. 打开 Stylus → 「管理样式」→「**编写新样式**」
2. 把 `bigballofmud-luogu.user.css` 的全部内容粘进去 → `Ctrl+S`
3. 打开洛谷刷新，即可看到效果

### 2. 脚本（可选）

1. 装 [Tampermonkey](https://www.tampermonkey.net/)
2. 油猴图标 → 「**添加新脚本**」→ 清空编辑区 → 粘贴 `bigballofmud-luogu-switch.user.js` 全部内容 → `Ctrl+S`
3. 刷新洛谷，顶栏「私信 / 通知」右边会出现一个圆形配色按钮

> **怎么区分两个文件？** 脚本文件第一行是 `// ==UserScript==`（油猴靠它识别）；
> 样式文件开头是 `/* ==UserStyle==`。粘错地方不会生效，但也不会弄坏什么。

## 配色切换（三种方式，任选）

| 方式 | 怎么做 | 是否需要脚本 |
|---|---|---|
| 顶栏按钮 | 点顶栏那个圆形图标，循环 跟随系统 → 深色 → 浅色，选择会记住 | 需要 |
| Stylus 面板 | 编辑样式，右侧「配色模式」下拉三选一 → 保存 | 不需要 |
| 改代码 | 把 ① 段的 `color-scheme: [[colorMode]];` 删掉，只留 `color-scheme: light dark;`（或写死 `light` / `dark`）| 不需要 |

## 都美化了哪些地方

- **液态玻璃质感**：不是单纯的毛玻璃 —— 有镜面光斑、亮上缘 / 暗下缘的"厚度"、内发光、
  以及靠强模糊 + 高饱和让背景颜色透上来的通透感；鼠标悬停时光斑会缓慢漂移
- **顶栏**：左右两个独立的玻璃胶囊，中间留空；高度与留白全站统一
- **左右侧栏**：悬浮胶囊（离开屏幕边缘 + 大圆角），滚动条隐藏，展开/收起状态各自正确
- **背景图**：透出到整页（洛谷默认只画顶部 400px 且有一层不透明底板挡住了图）
- **深色模式**：覆盖洛谷运行时注入的调色板令牌、写死的浅色文字、白底控件、
  各类弹窗与编辑器（SweetAlert2 / CodeMirror 6 / Casket / 题目排序面板 / 评测测试点方块…）
- **链接悬停**：渐变色文字 + 下划线从中间划入（犇犇、讨论区、文章正文都覆盖）
- **标签 / 徽章悬停**：一道高光扫过 + 轻微抬起
- **卡片、按钮、表单、浮层**：同一套玻璃语言，并带柔和阴影与悬停反馈

## 想调一调？

样式 ② 段集中了所有可调项，改一个数就能整体变化：

### 玻璃通透度（数值越小越透）

| 变量 | 默认 | 管什么 |
|---|---|---|
| `--lg-alpha` | `26%` | 主卡片 |
| `--lg-alpha-soft` | `20%` | 列表 / 表格 / 分页 / 搜索框 |
| `--lg-alpha-pop` | `26%` | 模态 / 下拉 / 气泡 / 通知（与卡片同值，避免色差）|
| `--lg-alpha-field` | `44%` | 输入框 / 文本域 / 下拉选择 |
| `--lg-nav-alpha` | `42%` | 顶栏两个胶囊 + 左右侧栏 |

### 液态玻璃质感

| 变量 | 默认 | 作用 |
|---|---|---|
| `--lg-blur` | `24px` | 浮层 / 顶栏 / 侧栏的模糊半径（越大越"液态"）|
| `--lg-card-blur` | `18px` | 卡片模糊（页面卡顿就调小，或设 `0`）|
| `--lg-sat` | `215%` | 背景饱和度提升（越高越能"看见"背景的颜色）|
| `--lg-spec` | `22%` | 镜面光斑强度（设 `0` 退回普通毛玻璃）|
| `--lg-rim` | `62%` | 上缘高光强度（玻璃厚度感）|
| `--lg-shade` | 见 ③-b | 背光侧暗缘（有它才有体积感）|
| `--lg-glow` | 见 ③-b | 内发光 |

### 尺寸与圆角

| 变量 | 默认 | 作用 |
|---|---|---|
| `--lg-topbar-h` | `63px` | 顶栏总高（胶囊高 = 它 − 2 × `--lg-topbar-gap`）|
| `--lg-topbar-gap` | `6px` | 胶囊与顶栏上下边缘的留白 |
| `--lg-radius` / `-sm` / `-xs` | `20 / 12 / 8px` | 大卡 / 中卡 / 小元件圆角 |
| `--lg-side-gap` | `10px` | 侧栏离屏幕边缘的距离 |
| `--lg-side-radius` | `26px` | 侧栏圆角 |
| `--sl-switch-duration` | `.14s` | 切深浅时的统一过渡时长 |

### 背景图

```css
--sl-bg-image: url("…");   /* 改这一行即可换图 */
```

不想要自定义背景图、想交回洛谷主题商店的话，把 ⑭ 整节删掉即可。

## 常见问题

**Q：装上之后右栏收不回去了？**
已经修好了。如果你想改侧栏悬浮参数：`--lg-side-gap`（离边缘距离）、`--lg-side-radius`（圆角）。

**Q：深色下某处还是白的 / 某段文字看不清？**
两件事可以试：
1. 确认 Stylus 里是最新版（在编辑器里搜一个特征字符串，例如 `--lg-pop-dark`，搜得到就是新版）
2. 装上可选脚本 —— 它的「对比度守卫」会读取**最终计算出来**的颜色，自动把不达标的文字修到可读

**Q：浅色模式和洛谷原版一样吗？**
一样。样式的浅色分支一律"就地消费"洛谷的主题变量，且深色重映射用的浅色值都等于洛谷原值
（本项目有一套校验脚本专门断言这一点）。

**Q：会和洛谷主题商店冲突吗？**
不会。样式不重写主题变量，只是消费它们；换主题色、换背景图，玻璃都会跟着变。

**Q：页面变卡？**
把 `--lg-card-blur` 调小（如 `8px`）或设 `0`；也可以把 `--lg-sat` 降到 `150%`。

**Q：手机上能用吗？**
未测试。样式是按桌面布局写的（顶栏胶囊、左右侧栏），移动端布局不同，可能需要另外适配。

## 兼容性

- **浏览器**：需要支持 `light-dark()`，即 Chrome / Edge 111+、Safari 16.4+、Firefox 120+。
  更老的浏览器会退化：文件里有 `@supports not (color: light-dark(#fff, #000))` 兜底块，
  保留固定浅色玻璃（深色模式不生效）。
- **站点范围**：只作用于 `www.luogu.com.cn` 主站。
  `ti.luogu.com.cn`（有题）与 `class.luogu.com.cn`（网校）是另外两套前端，本样式不覆盖。
- **随洛谷更新可能失效**：洛谷前端发版会改 DOM 结构与类名。本样式**刻意不使用** `data-v-*` 哈希
  （每构建都会变），但仍然依赖稳定的语义类名，洛谷大改版后个别地方可能需要跟进。

## 说明

这个项目的起点是"洛谷新版前端更新后，原有美化失效了"。
修复过程中所有结论都靠**取证**得出（下载前端产物分析、像素采样、DevTools 实证），
而不是靠猜 —— 项目内部保留了一整套校验脚本与证据记录，用于防止回归。
如果你在某个页面发现了没适配的地方，欢迎带着**那一处的类名或 DevTools 截图**提 issue，
这样能一次定位，比描述现象快得多。
